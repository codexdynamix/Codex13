# 1. MAIN GOAL

Create a professional email application inside the Codex Dynamics Client Portal.

The client must be able to use their Hostinger-hosted email accounts directly from the Codex Client Portal.

The client must NOT have to leave the Codex portal and open Hostinger Webmail.

# 7. TOKEN SAVE WORKFLOW

When Super Admin enters a token:

1. Super Admin opens Settings.
2. Opens Hostinger Mail API.
3. Enters the API token.
4. Clicks Save Token.
5. Backend receives the token through an authenticated HTTPS request.
6. Backend validates/tests the token against Hostinger.
7. If the token is valid:

   * securely store it
   * mark the Hostinger integration as connected
   * show success notification
8. If invalid:

   * do NOT activate the new token
   * do NOT overwrite a currently working token unless the new token has passed validation
   * show a clear error message
9. Never expose the token back to the frontend.

If a valid token already exists and the Super Admin replaces it:

1. Enter new token.
2. Test new token.
3. If successful, securely replace the old token.
4. The entire system immediately starts using the new token.
5. No source-code change.
6. No frontend rebuild specifically for the token.
7. No manual editing of PHP files.
8. No GitHub change required.

This is a critical requirement.
